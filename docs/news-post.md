# チャットからお知らせを投稿する

「◯◯に登壇しました、って上げといて」と言うだけで、microCMS への登録から
サイトへの反映まで通るようにしてあります。

```
チャットで内容を伝える
  → こちらで文面を作って確認してもらう
  → GitHub Actions が microCMS に登録
  → Webhook が Cloudflare を叩く
  → 1〜2分でサイトに出る
```

microCMS の管理画面を開く必要はありません。

---

## 準備（一度だけ・5分）

### 1. microCMS のAPIキーに書き込みを許可する

microCMS →「サービス設定」→「APIキー」

**いま使っているキーを開いて、`news` の `PUT` をオンにしてください。**
`DELETE` はオフのままにしておきます。誤操作で記事が消えるのを防ぐためです。

> **キーを2つ作れるなら**、投稿用を別に作ったほうが安全です。
> ただし無料プランではAPIキーを1つしか持てないので、その場合は
> 既存のキー（サイトが読み取りに使っているもの）に `PUT` を足す形になります。

#### 同じキーを使い回して大丈夫か

大丈夫です。このキーが置かれるのは次の2か所だけで、どちらも非公開です。

| 置き場所 | 用途 |
|---|---|
| Cloudflare Pages の環境変数（Secret） | ビルド時にお知らせを読む |
| GitHub の Actions Secrets | 投稿する |

**サイトの書き出し結果にキーは入りません。** Astro はビルドのときだけこのキーを使い、
出来上がった HTML / JS には残らないため、ブラウザからは見えません
（`PUBLIC_` で始まらない環境変数はクライアントに渡らない仕様です）。

万一どこかに漏らしてしまったときは、microCMS でキーを再発行して、
上の2か所を差し替えてください。

### 2. GitHub にも同じキーを登録する

> **なぜ Cloudflare ではなく GitHub なのか**
>
> Cloudflare に入れてあるキーは「サイトがビルド時にお知らせを**読む**」ためのものです。
> 投稿する処理はどこかで**動かす**必要があり、チャットから起動できるのが
> GitHub Actions だけなので、そちら側にもキーの控えが要ります。
>
> なお **Cloudflare に登録した Secret は後から中身を見られません。**
> コピー元は microCMS のAPIキー画面から取ってください。


`ozaken-AI/profile` → **Settings** → **Secrets and variables** → **Actions**
→ **Secrets** タブ → **New repository secret**

| Name | Secret |
|---|---|
| `MICROCMS_WRITE_API_KEY` | 1で作ったキー |

これで準備は終わりです。

## 使いかた

### チャットから

投稿したい内容を伝えてください。日付・カテゴリ・本文を組み立てて、
確認してもらってから登録します。

> 「昨日 AI・人工知能EXPO で基調講演したので、お知らせ上げといて」

うまく書けないときは、箇条書きのメモを投げてもらえれば整えます。

### 自分で操作する

GitHub の **Actions** タブ →「**お知らせを投稿**」→ **Run workflow**

| 欄 | 中身 |
|---|---|
| タイトル | 例：`日経メッセに登壇しました。` |
| カテゴリ | 登壇 ／ メディア ／ イベント ／ リリース |
| 本文 | **空行を入れるとそこで段落が分かれます**（リンクの書き方は下記） |
| 掲載日 | `2026-08-24` の形。空なら今日（日本時間） |
| 抜粋 | 空なら本文の書き出しから自動で作ります |
| イベント名 | 登壇のとき。任意 |
| 外部リンク | 入れると、一覧からその記事に直接飛びます |
| 記事ID | URLの末尾。空なら日付から自動 |
| 公開／下書き | 迷うときは下書きにして、microCMS で確認してから公開 |

実行が終わると、Actions の画面に登録内容とURLが出ます。

## 本文にリンクを入れる

次のどれで書いても、クリックできるリンクになります（別タブで開きます）。

```
<a href="https://example.com/">申込ページ</a>
[申込ページ](https://example.com/)
https://example.com/
```

URLをそのまま貼るだけでも構いません。**URLの直後の句点や読点は巻き込みません。**

これ以外のHTMLタグ（`<b>` や `<div>` など）は、そのままの文字として表示されます。
本文は原則すべてエスケープしていて、リンクだけを通しているためです。
見出しや箇条書きを使いたいときは、投稿したあと microCMS のリッチエディタで足してください。

### microCMS の画面で書く場合

リッチエディタでは、**リンクにしたい文字を選択してからリンクのボタン**を押します。
`<a href="...">` と直接打ち込むと、タグがそのまま文字として保存されてしまいます。

## よくあること

**写真を入れたい**
このワークフローでは画像を扱いません。投稿したあと microCMS で
`thumbnail` に写真をアップロードしてください（記事ページの冒頭とSNSシェア画像に出ます。
一覧はサムネイルなしの design です）。

**間違えた**
同じ記事IDでもう一度実行すると上書きされます。消したいときは microCMS から削除してください。

**サイトに出てこない**
microCMS には入っているのにサイトが変わらない場合は、Webhook かデプロイフックです。
`docs/microcms-setup.md` の5章を見てください。

**「MICROCMS_WRITE_API_KEY が設定されていません」と出た**
上の準備2が抜けています。

## 送る内容だけ確かめたいとき

手元に Node.js があれば、送らずに整形結果だけ見られます。

```bash
DRY_RUN=1 MICROCMS_WRITE_API_KEY=dummy \
IN_TITLE='テスト' IN_CATEGORY='登壇' IN_BODY='本文' \
node scripts/news-post.mjs
```
