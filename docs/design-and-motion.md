# デザインとアニメーションの引き継ぎ

最終確認：2026-09-07、PR #14時点。本人が気に入っている開幕・本文の動きを基準にする。[公開手順](operations.md)／[判断の記録](decisions.md)。

## デザインの軸

墨色・和紙・明朝体を基調に、光と粒子でAI時代の動きを加える。顔・言葉・実績を読みやすく保つ。資料サイトの青・紺・赤のデザインとは別系統なので、両サイトのCSSをそのまま移植しない。

書体は見出しにShippori Mincho B1、数字・英字にArchivo、本文にZen Kaku Gothic New。色・間隔・書体は `global.css` の共通変数を先に確認し、ページごとに無関係な値を増やさない。

本人の希望：動きを止めるボタンは置かない。OSの `prefers-reduced-motion`、画面外と非表示タブでの停止は維持する。装飾は `aria-hidden`・`pointer-events: none` を基本とし、文字選択やリンク操作を妨げない。

## 最初に開くとき

主な実装は `src/components/SiteEntrance.astro`、`src/pages/index.astro`、`src/styles/global.css`。

1. 最初は黒い画面。分断した線がつながる演出から、実際の見出しの文字へ展開する。
2. **「人間とAIが／共存する社会を／つくる。」を先に読む時間を取る。** 顔写真・肩書き・CTAが同時に競わないようにする。
3. 後半の光は外へ散る。散った光を再び内側へ収束させない。
4. 開幕がそのままトップの粒子と空間へつながる。

地球のような球体、最初から顔の上にある光、トップと別世界に見える独立したローディング画面には戻さない。

現行の時間配分は次のとおり。秒数を変える場合はCSSとcanvasの進行を一緒に調整する。

| 要素 | 現行の目安 |
|---|---|
| 見出しの展開 | 各0.72秒、遅延0.5 / 0.6 / 0.7秒。最後は約1.42秒で展開完了 |
| 見出し以外の説明 | 1.95秒後から0.65秒で表示 |
| CTA | 2.15秒後から表示 |
| 写真 | 遅延0.9秒＋1.85秒の展開。暗幕との合成で早期露出を抑える |
| 黒い暗幕 | 2.8秒。前半60%はほぼ黒い状態を維持 |
| 開幕全体 | 約3.15秒、3.5秒の終了保険 |

ポインター・キー・スクロール・タッチ等での終了、リサイズ、ページ離脱、タブ非表示、動きを減らす設定への対応を残す。アニメーションが失敗しても本文が読めること。

### 重なり順で起きた問題を繰り返さない

固定暗幕 `body::after` は `z-index: 80`、実際の `.hero-inner` は81、開幕レイヤーは82。この関係で見出しが暗幕の上に現れる。ページ全体の祖先へ `transform`・`isolation` などを追加し、新しい重なりの境界の中にヒーローを閉じ込めると、文字も暗幕の下に隠れる。共通レイアウト変更時は必ず最初の黒い状態から確認する。

## トップの常時粒子

`src/components/HeroDust.astro`。36個の粒子面が上昇・横揺れし、周期は8〜20秒。開幕後も動きを残す。IntersectionObserver・タブの可視状態で休止する。

本人は「もう少し動きがあるもの」を希望した経緯がある。修正後に粒子が静止したり、開幕終了と同時に消えたりしていないか確認する。

## ファーストビュー以外の動き

`src/components/SiteMotion.astro` を `Base.astro` から読み込む。各対象セクション（band / phead / contact、フッター）の背後に装飾を作る。セクション内の独立した重なりと負のz-indexで、本文の後ろに置く。

PR #14の基準値：

| 要素 | 現行の設定 |
|---|---|
| 塵 | PC16個、600px以下9個。約1〜2.2px、周期12〜18.8秒 |
| 光の移動 | 22秒と29秒でゆっくり往復 |
| 光量の増減 | 移動とは独立して9秒と12秒の周期 |
| 光の透明度 | before側0.2〜1、after側0.12〜0.75 |
| 色 | 暗い面は青寄り、和紙の面は暖色。和紙側の全体透明度0.65 |
| 写真 | 約1.025〜1.065のゆっくりした拡大、16秒・19秒 |
| セクションラベル | 7秒周期の光の通過 |

背景レイヤーは高さ最大1600px、上下80pxのマスクで境界をなじませる。大きな光の移動と明るさの変化を別の周期にし、全セクションが同じ瞬間に点滅する印象を避けている。

### IntersectionObserverの境界

PR #13では、画面端で `isIntersecting: true` でも交差面積が0になるケースを修正した。threshold 0では、そこから面積が増えても次の通知が来ない場合がある。**`isIntersecting` に加えて交差高さが正であることを要求しない。** 現行は `isIntersecting` を使って `motion-active` を切り替える。条件を戻すと、お知らせ以降の背景が停止したままになる。

## LINEの隠しコマンド

実装はトップの `src/pages/index.astro`。リンク先の値は `SITE.line`、QRは `src/assets/line-qr.svg`。

- PC：`ozaken` と順番に入力。フォーム・入力欄・編集可能要素・修飾キー操作を妨げない。
- タッチ：ヒーローの肩書き行 → 見出しの領域 → スクロール案内の順に触れる。各操作間は6秒以内。
- dialogの開閉、Esc、外側タップ、フォーカス、リンクとコピーを確認する。コピーAPIが使えない場合の代替処理を残す。
- リンク先を変える場合はQRも更新する。公開ナビゲーションに新たなLINEボタンを常設しない。

これは見つける楽しみのための仕掛けであり、認証や機密保護ではない。現行のdialog表示には `line_click` 計測がない。[解析上の制約](analytics.md)も参照する。

## 修正後の画面確認

PC、390px、狭い320pxで確認する。開幕を最初から再生し、見出しの先行、暗幕解除、トップの動き、LINEの操作を確認。次に暗いセクションと和紙のセクションをスクロールし、光の明暗が変わっても文字・リンクが読めることを確かめる。

画面端にセクションが接した状態からのスクロールも試す。PR #13の再現では1304×1128の画面でお知らせの端が接した状態が有効だった。時間差の位置・透明度、画面外停止、タブ再表示を確認する。下層ページと共通ヘッダーも対象にする。

OSの設定を実際に切り替えていない場合、「動きを減らす設定はコードで確認」と報告し、実機確認済みと書かない。
