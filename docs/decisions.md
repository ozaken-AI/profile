## 確認済みと、毎回確認するもの

- 確認済み：プロフィール側の既定ブランチは `claude/ozaken-portfolio-site-a0aggr`。資料側は `main`。両方とも公開リポジトリ。
- ソースから確認できるもの：CMSのキー未設定時にビルドが通ること、キーがあるのに取得できないときにビルドが失敗すること、フォームの代替動作、アニメーションの停止条件。ソースだけでは外部サービスの現在の設定や配送成功は証明できない。
- 2026-09-09：CMSの取得失敗でビルドを止める方針に変更した。従来は失敗しても空配列を返してビルドが成功し、`/news/<id>/` が1枚も生成されないサイトがそのまま公開されうる状態だった。Search Consoleが404と「重複・別ページが正規」を報告したのを機に修正。ビルドを失敗させれば Cloudflare Pages は直前の正常なデプロイを残す。実装は `src/lib/microcms.ts` の `getNews`。
- 文書作成では、秘密情報の値の取得、実メール送信、CMS投稿、資料公開、名簿の取り込みは行っていない。手順の記録と実運用の実施を区別する。
- 既存の技術的制約：`astro check` 用の依存は未登録。非推奨 `execCommand` と未使用 `Props` のヒントがある。詳細は[運用ガイド](operations.md)。
- 情報の追従が必要な箇所：OGPの元HTMLに旧表記が残る。将来の再生成時に期間付きの実績へ同期する。今回の文書整備で画像自体は変更していない。
