# 旧サイトのお知らせ移行の記録

2026-08の旧サイトからの移行用。**日常の投稿・訂正や、現在の記事を復元するためのバックアップではない。** 日常運用は [投稿手順](news-post.md)。本書の実装確認：2026-09-07。

## 対象とファイル

旧サイト `ozaken-ai.studio.site` の232件（2023-10-15〜2026-07-29）。分類は登壇113、メディア99、リリース16、イベント4。機械分類なので、現在のCMSで訂正された内容とは異なる可能性がある。**232は移行時の件数であり、現在の記事総数ではない。**

| ファイル | 用途 |
|---|---|
| [cms_content_20260824.json](legacy/cms_content_20260824.json) | 旧サイトから抽出した原データ |
| [news-import.json](legacy/news-import.json) | API投入用の変換データ |
| [news-import.csv](legacy/news-import.csv) | セレクトをJSON配列表記にしたCSV |
| [news-import-plain.csv](legacy/news-import-plain.csv) | セレクトを通常の文字列にしたCSV |
| `scripts/news-build-import.mjs` | 上記の原データからJSON・CSVを再生成 |
| `scripts/news-import.mjs` | 変換JSONをCMSへPUTする移行用スクリプト |

タイトル・掲載日・本文・抜粋を移し、`externalUrl` は空。旧サムネイルは移行していない。必要なら原データに残るURLを調べる。

## 再移行を始める前に

既存CMSのエクスポート・対象ID・新旧差分を確認し、追加・訂正・不要なものを分ける。すでに取り込んだ232件をそのまま再投入しない。IDは小文字化、英字の先頭追加、衝突回避の連番等で正規化されており、旧スラッグそのままとは限らない。

再生成はローカルの移行ファイルを上書きする。修正したい分類や列を明確にし、作業ブランチと差分で保護してから行う。

```bash
node scripts/news-build-import.mjs
```

## CSVを使う場合

[CMSスキーマ](microcms-setup.md)とエクスポートした現在のCSVを照合する。現行の移行CSVはID＋11フィールドの12列。

```text
id,title,category,publishedDate,excerpt,thumbnail,body,externalUrl,eventName,audience,scale,location
```

列数が違う場合、現在のスキーマに追加されたフィールドがないか確認する。CSVを通すためだけにCMSフィールドを削除しない。カテゴリの選択肢が空だった過去事例があるため、まず4つの選択肢と保存状態を調べる。

セレクトの期待表記は、現在のCMSからのエクスポートで確認してCSVを合わせる。配列版と文字列版を、本番へ無計画に順番に投入しない。インポート上限や重複時の扱いは現在の管理画面・仕様で確認する。

## スクリプトを使う場合

Node.jsで `scripts/news-import.mjs` を実行する。環境の `MICROCMS_WRITE_API_KEY`（PUT）が優先され、なければ `MICROCMS_API_KEY` が参照される。読み取りキーだけでは書き込めない。キーは値をコマンドに埋め込まず、安全な環境設定で渡す。

送信せずに確認する例。dry-runもキーの存在を要求するためダミーを指定する。

```bash
MICROCMS_WRITE_API_KEY=dummy node scripts/news-import.mjs --dry-run
```

実投入のコマンドは `node scripts/news-import.mjs`。これはCMSを書き換える操作なので、対象を確定した移行時だけ行う。

**この移行スクリプトはPUTのみ。既存IDをPATCHで更新しない。** 既存IDはエラーになるため、「何度実行しても同じ結果」「途中で止まったらそのまま再実行」と扱わない。途中失敗時は成功・失敗IDを記録し、未登録分を特定する。429や5xxの一時エラーはコード内で再試行するが、既存IDの上書き保証ではない。

一時的な移行用キーを廃止する場合も、日常の投稿workflow等で使っていないことを確認する。

## 反映の確認

一括投入ではWebhookが大量のビルドを起動する可能性がある。契約上限と実行状況を確認し、一時停止が必要なら元の設定を記録して作業後に戻す。最後に本番対象のビルドを行い、追加対象と既存記事が残っていること、カテゴリ・日付・詳細リンクを確認する。

現在の `getNews()` の既定取得上限は500件。件数が増えた際は、この上限とサイトマップを確認する。復旧対象が現在のCMSであれば、旧サイトのスナップショットで置き換えず、現在のバックアップを使う。
