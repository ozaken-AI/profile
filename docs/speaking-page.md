# 講演・研修・組織変革の統合ページ

最終更新：2026-09-11。本人の「2つのページの遷移が分かりづらい。一緒のページでいいのでは」という希望に対応。一覧から詳細へ往復する構成をやめ、`/speaking/` の1ページで内容・条件・実績を比較できるようにする。

## 構成と編集先

入口の3形式 → 講演3テーマ → 研修4種類と匿名実績 → 顧問・アドバイザー（経営判断／組織への浸透、支援実績、条件）→ 登壇先 → 相談から契約まで → 共通FAQ → 相談先、の順。対象者と持ち帰る視点は折りたたまない。比較用のページ内ナビを途中でも使えるようにする。補足の論点・進め方・構成例・公開先の長い一覧は、同じページの `details` で開く。JavaScriptに依存するタブ切り替えは使わない。

| 内容 | 編集先 |
|---|---|
| 全体構成、入口、共通の流れ、title・description・ServiceのJSON-LD | `src/pages/speaking/index.astro` |

問い合わせの新規入口は `kind=keynote/training/advisory`。旧 `partner` は顧問の浸透・定着の相談として引き継ぐ。料金は個別見積もり。代表的な登壇の紹介枠は本人の希望に従い復活させない。

2026-09-11に本人が確認した希望により、組織変革も顧問・アドバイザーとして関わることを明記。その後、本人から重複を指摘されたため、2つを `#advisory` に統合した。経営判断と組織への浸透は、その中の相談領域として説明する。[評価・変更理由・互換性](information-structure.md)を参照。

## 旧URLと検証

旧 `/speaking/keynote/`、`training/`、`partner/`、`advisory/` は、末尾スラッシュの有無を含め `/speaking/` へ301転送。転送先に固定のフラグメントを指定せず、従来共有した `#keynote-series`、`#management`、`#organization`、`#trends`、`#program`、`#conditions` を引き継げるようにする。新規リンクは直接 `/speaking/#training` 等へ向ける。

Cloudflare Pagesでは `public/_redirects` がHTTP転送を担う。Astroの静的リダイレクトHTMLは、ローカルプレビュー等の代替。サイトマップには統合ページだけを含め、旧ページを再生成して重複コンテンツにしない。

更新時は以下を確認する。

1. ビルド・型診断。H1が1つ、canonicalが `/speaking/`、3つのServiceと表示内容が一致すること。
2. 内部リンク先のアンカーが存在すること。旧8URLのHTTP転送、旧基調講演のフラグメント、新しい相談リンクの `kind`。
3. PC・390px・320pxの表示、横はみ出し、開閉のクリック／Enter操作、開いた内容の可視性、背景の動き。
4. 差分と配信HTMLに非公開の実社名が入っていないこと。匿名5件に新しい成果や製品を付け足していないこと。
5. マージコミットのデプロイ成功と本番URL。本番トップのお知らせ8件が残っていること。CMS未設定のプレビューは空になるため本番とは区別する。

## 2026-09-11の監査反映

- 入口の定義は `FORMATS` をトップと統合ページで共有する。研修は `TRAINING_PROGRAMS.id` で相談フォームへ引き継ぐ。
- 講演の各テーマには相談、企画概要の印刷、共有リンクのコピーがある。印刷は同じページの `data-print-talk` とprint CSSで対象テーマだけを出す。別のサービス詳細ページや、手動同期するPDFを増やさない。印刷終了時に状態を解除する。
- 企業実績は研修3件、全社推進2件を説明の近くに置く。`#engagements` は研修実績そのものへ、`#advisory-evidence` は顧問内の全社推進実績へ移動する。
- 本人が確認した相談課題は「生成AIの活用率が上がらない」「組織全体に浸透しない」「表層的な活用に止まる」。`ORGANIZATION_CHALLENGES` は相談例と支援方針であり、特定案件の成果・改善率として扱わない。
- 匿名案件ごとの担当範囲・期間・人数・成果は未確認。増補する場合は本人確認が必要。
