# microCMS のセットアップ手順

お知らせ（登壇報告・メディア掲載・リリース）を管理するための設定。
**このとおりにフィールドを作ってください。** フィールドIDが違うと実装側が読めません。

所要時間は15分ほど。無料の Hobby プランで足ります。

---

## 1. アカウントとサービスを作る

1. https://microcms.io/ で登録
2. サービスを作成
   - サービス名：`ozaken.ai`（任意）
   - **サービスID：`ozaken`**（任意だが、決めたら教えてください。APIのURLに入ります）

---

## 2. API を作る

**コンテンツ（API）を作成** から、以下のとおり作ります。

- API名：**お知らせ**
- エンドポイント：**`news`**
- **型：リスト形式**

---

## 3. フィールドを定義する

「APIスキーマ」で下の11個を作ります。フィールドIDは**半角英字でこのとおり**にしてください。

| # | フィールドID | 表示名 | 種類 | 必須 | 備考 |
|---|---|---|---|---|---|
| 1 | `title` | タイトル | テキストフィールド | ✓ | |
| 2 | `category` | カテゴリ | セレクトフィールド | ✓ | 選択肢は下記。**複数選択はオフ** |
| 3 | `publishedDate` | 掲載日 | 日時 | ✓ | 下の「なぜ日付を自前で持つか」参照 |
| 4 | `excerpt` | 抜粋 | テキストエリア | | 一覧とSNSシェアに出る2〜3行 |
| 5 | `thumbnail` | サムネイル | 画像 | | 記事ページの冒頭とOGPに使う。一覧には出ない |
| 6 | `body` | 本文 | リッチエディタ | | 空でも可。空なら一覧だけに出る |
| 7 | `externalUrl` | 外部リンク | テキストフィールド | | 入れると詳細ページを作らず直接飛ばす |
| 8 | `eventName` | イベント名 | テキストフィールド | | 登壇のとき |
| 9 | `audience` | 対象者 | テキストフィールド | | 登壇のとき（例：経営層・事業部長） |
| 10 | `scale` | 規模 | テキストフィールド | | 登壇のとき（例：約420名） |
| 11 | `location` | 場所 | テキストフィールド | | 登壇のとき（例：東京・大手町／オンライン） |

### `category` の選択肢

**セレクトフィールドの「選択肢」に、この4つをこの順で**登録してください。

```
登壇
メディア
イベント
リリース
```

**スキーマをJSONでインポートした場合、選択肢だけが入らないことがあります。**
記事の編集画面でカテゴリを開いて「Select」しか出てこないときは、選択肢が空です。

#### 選択肢の足しかた

1. 「お知らせ」の画面の右上 **API設定**
2. 左メニューの **APIスキーマ**
3. フィールド一覧の `category` の行をクリック（編集のアイコンでも可）
4. 開いたパネルの中に **選択肢** の入力欄がある
   - `登壇` と入力 → **追加**（または Enter）
   - 同じように `メディア` `イベント` `リリース` を足す
   - **複数選択で入力する** は**オフのまま**
5. パネルの **変更** で確定
6. **画面の「変更を保存」を押す** ← ここを押さないと反映されません

#### 確認

記事の新規作成画面を開いて、カテゴリのプルダウンに4つ出てくればOKです。
「Select」しか出てこないなら、6の保存が抜けています。

#### どうしても入らないとき

`category` の種類を **セレクトフィールド → テキストフィールド** に変えても動きます。
サイト側はどちらでも読めるようにしてあります。
そのかわり入力時に選択肢が出ないので、`登壇` `メディア` `イベント` `リリース` を
毎回手で書くことになります（表記がぶれると絞り込みが分かれます）。

8〜11 は登壇のときだけ埋めれば十分です。空欄なら表示されません。

**一覧はサムネイルを出しません。** 日付・カテゴリ・タイトルだけの行で並びます。
`thumbnail` を入れた記事は、記事ページの冒頭とSNSシェア画像にだけ使われます。

---

## 4. API キーを発行する

「サービス設定」→「APIキー」から、**GET だけ許可した**キーを1つ作ります。

- `GET` … ✓ オンにする
- `POST` / `PUT` / `PATCH` / `DELETE` … オフのまま

サイトは読み取りしかしないので、書き込み権限は付けないでください。

発行したら、**サービスIDとAPIキーを教えてください。** Cloudflare の環境変数に入れます。
チャットに貼る形で構いませんが、気になる場合は Cloudflare の画面から直接登録してもらっても大丈夫です
（その場合は変数名だけこちらから伝えます）。

---

## 5. 公開したら自動でサイトに反映されるようにする

**サイトは microCMS を「ビルドのときだけ」読みます。** CMSで公開ボタンを押しても、
再デプロイするまで公開ページは変わりません。これを自動でやるのが以下の設定です。

### 5-1. Cloudflare でデプロイフックを作る

Cloudflare ダッシュボード → **Workers & Pages** → `profile` → **Settings** →
**Build** の中の **Deploy hooks** → **Add deploy hook**

- Deploy hook name：`microcms`
- Branch to build：`claude/ozaken-portfolio-site-a0aggr`
  （本番として設定しているブランチ。Production branch と同じものを選ぶ）

作ると `https://api.cloudflare.com/client/v4/pages/webhooks/deploy_hooks/xxxxxxxx`
のような URL が出るのでコピーします。

**この URL を知っている人は誰でもビルドを走らせられます。** 人に見せないでください。

### 5-2. microCMS の Webhook に登録する

microCMS → **お知らせ（news）** → **API設定** → **Webhook** → **追加**

- 種類：**カスタム通知**
- URL：5-1でコピーしたもの
- 通知タイミング：**コンテンツの公開・更新・公開終了・削除** にチェック

（下書き保存では動かないようにしておくと、余計なビルドが走りません）

### 5-3. 確認する

microCMS で適当な記事を1つ公開してみて、

1. Cloudflare の **Deployments** に新しいビルドが積まれる
2. 1〜2分で `https://ozaken.ai/news/` に反映される

ここまで来れば完了です。以降は microCMS で公開ボタンを押すだけで反映されます。

### 反映されないとき

- **ビルドが始まらない** … Webhook の URL を確認。microCMS の Webhook 画面に
  実行ログが残るので、そこにエラーが出ていないか見る
- **ビルドは走るがお知らせが空** … Cloudflare の環境変数
  `MICROCMS_SERVICE_DOMAIN` と `MICROCMS_API_KEY` が Production に入っているか。
  取得に失敗してもビルドは通る作りなので、記事だけ空になります

## なぜ日付を自前で持つのか

microCMS には `publishedAt`（公開日時）が最初から入っています。それを使わず `publishedDate` を
別に作るのは、**過去の登壇をあとからまとめて登録できるようにする**ためです。

`publishedAt` は「CMSで公開ボタンを押した日時」なので、先月の登壇を今日入力すると今日の日付になります。
実績として並べるときに困るので、実際の開催日を入れる欄を分けています。

## 入力例

### 登壇のとき

```
title        : AIエージェントは、仕事の主語を変える
category     : 登壇
publishedDate: 2026-07-16
excerpt      : 「AIに任せる」ではなく「どの判断を人が握り続けるか」から設計する話をしました。
thumbnail    : （当日の写真）
eventName    : 製造業サミット 2026
audience     : 経営層・事業部長
scale        : 約420名
location     : 東京・大手町
```

### メディア掲載のとき（外部記事に飛ばす）

```
title      : 日経クロステックに寄稿しました
category   : メディア
publishedDate: 2026-08-21
excerpt    : AIエージェント導入でつまずく3つのパターンについて書きました。
externalUrl: https://xtech.nikkei.com/...
```

`externalUrl` を入れると、一覧のタイトルが直接その記事に飛びます。詳細ページは作られません。

---

## 運用のこつ

- **抜粋（excerpt）は必ず入れてください。** 一覧の読みやすさと、SNSでシェアされたときの見え方が変わります
- **サムネイルは任意です。** 入れると記事ページの冒頭とSNSシェア画像に使われます。横長（16:9）が収まりがいいです
- 本文が空でも成立します。まず1行の報告だけ投げて、あとから加筆する使い方で構いません

## 補足：スキーマはインポートできます

手で11個作らなくて済みます。**`docs/microcms-news-schema.json` をインポートしてください。**

1. microCMS でコンテンツ（API）を作成する
   - API名：**お知らせ** ／ エンドポイント：**`news`** ／ **型：リスト形式**
2. 「APIスキーマを定義」の画面で **To import files, click here**（ファイルをインポート）を押す
3. `docs/microcms-news-schema.json` を選ぶ
4. フィールドが11個入るので、そのまま保存

ファイルはこのリポジトリの `docs/` にあります。GitHub の画面から
**Download raw file** でダウンロードできます。

### インポートが弾かれた場合

microCMS 側の仕様変更でフィールドの型名が変わることがあります。エラーが出たら、
どのフィールドで止まったか教えてください。JSONを直します。

エラーになったフィールドだけ JSON から削って残りをインポートし、
止まった1つを手で足す、という進め方でも構いません。型はこの表のとおりです。

| フィールドID | 種類 |
|---|---|
| `title` | テキストフィールド |
| `category` | セレクトフィールド（複数選択オフ） |
| `publishedDate` | 日時 |
| `excerpt` | テキストエリア |
| `thumbnail` | 画像 |
| `body` | リッチエディタ |
| `externalUrl` | テキストフィールド |
| `eventName` | テキストフィールド |
| `audience` | テキストフィールド |
| `scale` | テキストフィールド |
| `location` | テキストフィールド |
