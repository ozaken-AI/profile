# 情報の重複の評価と整理

2026-09-11。本人の「情報が被っているところを評価して、修正」という依頼への対応。トップ、統合依頼ページ、プロフィール、プレスキット、問い合わせ、共通の案内と公開用メタ情報を確認した。

## 評価と変更

| 重複・迷いやすさ | 判断と変更 |
|---|---|
| 組織変革と顧問が、いずれも経営陣への継続的なAI活用支援を説明 | 顧問・アドバイザーへ統合。中を「経営・事業の判断」「組織への浸透・定着」に分ける。条件・進め方・相談先は1組にする |
| 4形式の入口が、統合したサービスを別々の依頼として扱う | トップ、依頼ページ、フォーム、Service JSON-LD、共有画像を3形式へ同期。執筆・取材等の問い合わせは引き続き受け付ける |
| 比較カードの目的と「持ち帰るもの」が似た内容を繰り返す | 比較カードはサービス名・目的・扱う内容に絞る。具体的な持ち帰る視点は講演テーマで説明する |
| 研修の利用環境確認が本文と条件表に重複、FAQの冒頭が最初の費用回答を繰り返す | 研修の確認事項は条件表へ集約。費用・交通費・資料共有の詳細はFAQの各回答で説明する |
| 組織変革の課題3件、領域4件、顧問の相談例と進め方が同じ支援を繰り返す | 2つの領域で扱う内容を説明。本人確認済みの課題3件は短い相談例として残し、進め方は共通の1組に統合 |
| 顧問の公開役職3件を出した後、別の活動先一覧にも再掲 | 顧問セクション内の活動先一覧へ集約。役職の正式表記はプロフィールにリンク。登壇先は別の役割として区別する |
| トップで役職付きの組織を示した後、組織名だけの一覧を繰り返す | 組織名だけの一覧をトップから外す。役職付きの紹介・出典リンクは維持する |
| トップの依頼紹介と人物紹介が、同じ経歴・理念を説明 | 依頼紹介は選び方、人物紹介は経歴を担当。ヒーローと同趣旨のプロフィール段落を削除 |
| 全体の流れと、個々のサービスの実施手順の混在 | 全体は「ご相談から契約まで」、各サービスは実施・支援の進め方にする |

## 残す再掲

別ページから直接訪れた人に必要な氏名、短いプロフィール、相談先、個別見積もりの案内は維持する。トップの要約とプロフィールの詳細、告知用にコピーする短長のプロフィール文は用途が異なる。数字や肩書きは共通定義から表示し、文面が重なるだけを理由に削らない。CMSの個別のお知らせも、依頼メニューとは目的が異なるため変更しない。

## 互換性

- 新規のサービス入口は `keynote` / `training` / `advisory`。
- `#advisory` は統合セクション、旧 `#organization-change` はその中の浸透・定着の領域へ移動する。講演の `#organization` と混同しない。
- 旧 `kind=partner` と旧日本語ラベルは `contactSelection` で顧問へ変換し、「組織への浸透・定着」の相談意図を保持。旧「アドバイザリー・顧問」も認識する。過去のアクセス解析値を書き換えるものではない。
- 顧問の相談内容は `ai-strategy` / `ai-adoption` / `other-advisory`。講演・研修の「その他」は維持する。
- `#engagements` は研修実績そのものへ、`#advisory-evidence` は継続支援の実績へ案内する。

## 検証

ビルド・型診断、受信処理の模擬テスト、PC・390px・320pxでの表示、旧アンカーと旧フォーム種別、相談内容の選択を確認する。H1とIDの重複がなく、表示する3形式とService JSON-LDが一致することも確認。公開後は本番コミットの配信成功と最新ニュース8件を確認する。実メール送信やCMS投稿をテストに使用しない。
