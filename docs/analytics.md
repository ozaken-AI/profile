# アクセス解析と検索の運用

実装確認：2026-09-07。[APIからの取得](analytics-api.md)。この文書はコードが送る内容と読み方を記録する。GA4 / Search Consoleの現在の設定・データの存在は別途確認する。

## タグと設定

`src/layouts/Base.astro` はビルド環境の `PUBLIC_GA_ID` があるときだけGA4タグを出す。Cloudflare Pages `profile` のProductionに測定ID（`G-...`）を設定し、その設定で再ビルドする。IDは公開される設定値であり秘密鍵ではない。秘密情報を `PUBLIC_` 変数に入れない。

Previewやローカルも、値を渡せば計測対象になる。自動的にすべてのプレビューを除外する実装ではない。環境ごとの設定とGA4の内部トラフィック処理を確認し、検証時のアクセスを区別する。

タグの存在はソース・ネットワーク・GA4の受信状況で確認する。タグがあるだけで計測成功と断定しない。拡張計測の外部クリックと独自の `outbound_click` を、分析時に二重合算しない。

Search Consoleは実際に所有権を確認したプロパティを使う。サイトマップは **`https://ozaken.ai/sitemap-index.xml`**。所有権の確認方法や利用できる設定画面は作業時に確認する。反映の遅延・欠測をアクセスゼロと決めつけない。

## 現行イベント

| イベント | 発生時点 | パラメータ |
|---|---|---|
| `contact_cta` | `/contact/` へのリンクをクリック | `from`（元ページ）、`label`（リンク文字）、`kind`、`topic`、`place`（設置場所） |
| `contact_start` | 最初の入力・選択変更 | `kind`、`topic` |
| `contact_submit` | フォームの送信処理の結果 | `kind`、`topic`、`result`: `ok` / `エラー` / `通信失敗` / `メーラーに切替` |
| `outbound_click` | HTTP(S)の外部リンクをクリック | `url`（遷移先）、`page`（元ページ） |

**`contact_submit` の総数を送信成功数にしない。** 成功として集計する場合は `result = ok` を分ける。メーラーへの切替は、その後の送信完了をサイトから確認できない。bot対策の見かけの成功もあるため、このイベントが人間の有効な相談件数を完全に表すわけではない。

`contact_cta` は相談ページへの関心であり、送信・受注を意味しない。キーイベントの設定を変更する場合も、成功条件を確認してから行う。イベントを発生させるためだけに実フォームを送信しない。

### LINE計測の注意

現行トップのLINE dialogを開く処理は **`line_click` を送信していない**。`scripts/analytics-report.mjs` は過去との比較用の集計項目として `line_click` / `place` を残している。現在の件数が0でも「誰も隠しコマンドを使っていない」と結論しない。

外部リンクの計測は捕捉側（`capture: true`）で登録されている。途中で `stopPropagation()` する部品内のリンクも拾うためで、バブリング側へ変更する場合は影響を確認する。LINEの表示回数と実際の外部リンククリックは別の操作。

## 何を見て改善するか

- ページ・参照元・端末別の閲覧と、相談導線のクリックを組み合わせる。
- `contact_cta` の `from` で、どの依頼ページから相談へ進んだかを見る。
- `contact_submit` の `result` で、成功とエラー・メーラーへの切替を分ける。
- Search Consoleの検索語・表示回数・クリック・順位を、対象期間とページの変更日をそろえて読む。
- `trend` は検索推移の比較。旧サイトの順位や、計測開始前の欠測を含む完全な履歴ではない。

数字には対象期間、取得日時、データ元、未反映・権限不足等の制約を添える。個人を特定する問い合わせ情報と解析ログを不用意に結び付けない。集計結果を自動で公開Gitへ書き込まない。

## 実装とプライバシー

タグ・共通イベントは `Base.astro`、フォーム結果は `src/pages/contact.astro`、取得は `scripts/analytics-report.mjs`。設定では `allow_google_signals: false`、`allow_ad_personalization_signals: false`、`anonymize_ip: true` を渡している。

計測項目・外部送信先・利用目的を変える場合は `/privacy/` の記載も更新する。上記の設定だけであらゆる地域の法的要件を満たすと説明しない。新たな同意管理等が必要な変更では、対象条件に応じて確認する。

## 2026-09-11の依頼別計測

`kind` は `src/lib/contact.js` の固定ID（keynote/training/partner/advisory/writing/media/other）。`topic` は同じファイルの許可されたIDかunspecified。フォーム本文・氏名・メールアドレスをイベントへ渡さない。送信成功はフォームをresetする前の種別・テーマを記録する。

GA4の管理画面でカスタムディメンションを定義することと、コードからイベントを送ることは別作業。今回のコード変更だけでGA4レポートの項目登録や受信確認が完了したと扱わない。公開URLのクエリに非公開情報を入れない。
