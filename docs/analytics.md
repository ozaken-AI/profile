# サイトの分析をはじめる

やることは2つ。**Google アナリティクス（GA4）** と **Search Console** です。
どちらも無料で、合わせて30分ほど。サイト側の実装はもう入っています。

---

## 1. GA4 のプロパティを作る

1. <https://analytics.google.com/> を開く
2. **管理**（左下の歯車）→ **作成** → **プロパティ**
3. プロパティ名 `ozaken.ai` ／ タイムゾーン **日本** ／ 通貨 **日本円**
4. 業種とビジネス規模は適当で構いません（あとで変えられます）
5. 「データストリーム」で **ウェブ** を選ぶ
   - ウェブサイトのURL：`https://ozaken.ai`
   - ストリーム名：`ozaken.ai`
6. 作成後に出る **測定ID**（`G-` で始まる文字列）をコピー

### 拡張計測は切っておく

ストリームの設定に「拡張計測機能」があります。既定で「離脱クリック」「スクロール数」などが
自動で入りますが、こちらで意図した名前のイベントを送っているので、重複して分かりにくくなります。
**「離脱クリック」だけは切って**ください。他はそのままで構いません。

---

## 2. 測定IDを Cloudflare に入れる

1. Cloudflare のダッシュボード → **Workers & Pages** → 対象のプロジェクト
2. **設定** → **環境変数** → **本番環境**
3. 追加する：

   | 変数名 | 値 | 種別 |
   |---|---|---|
   | `PUBLIC_GA_ID` | `G-XXXXXXXXXX` | テキスト（Secretにしない） |

   > `PUBLIC_` で始まる変数はブラウザ側に出ます。測定IDは公開されて構わないものなので、
   > Secret ではなく **テキスト** で入れてください。Secret にすると読み出せず、扱いに困ります。

4. 保存したら **再デプロイ**（環境変数はビルド時に埋め込まれるため、保存しただけでは反映されません）

### 入っているか確かめる

サイトを開いてページのソースを表示し、`googletagmanager` で検索して1件出れば入っています。
**変数が未設定なら、タグは1行も出ません。** 開発中やプレビューで数字が汚れないようにしてあります。

---

## 3. Search Console に登録する

1. <https://search.google.com/search-console> を開く
2. **プロパティを追加** → **URLプレフィックス** に `https://ozaken.ai` を入力
3. 所有権の確認は **「Googleアナリティクス」** を選ぶのが一番早いです
   （手順2が終わっていれば、ボタン1つで通ります）
4. 通ったら、左メニューの **サイトマップ** に `sitemap-index.xml` を送信
   （`sitemap.xml` という名前のファイルは存在しないので注意）

これで「どんな言葉で検索されて来たか」「掲載順位」「インデックスの状況」が見られます。
数字が出るまで2〜3日かかります。

---

## 4. 見るべき数字

### 自動で取れるもの

- ページごとの閲覧数（依頼の4ページ、お知らせの各記事）
- 参照元（X / Facebook / 検索 / 直接）
- 地域、端末、ブラウザ

### こちらで送っているイベント

| イベント名 | いつ | 一緒に送る値 |
|---|---|---|
| `contact_submit` | お問い合わせフォームを送信したとき | `result`：`ok` ／ `エラー` ／ `通信失敗` ／ `メーラーに切替` |
| `contact_cta` | サイト内から `/contact/` へのリンクを押したとき | `from`：どのページから ／ `label`：押したリンクの文言 |
| `outbound_click` | 外部サイトへのリンクを押したとき | `url`：遷移先 |

**一番見る価値があるのは `contact_cta` の `from` です。**
4つの依頼ページのどれが実際に相談につながっているかが、これで分かります。

### 「キーイベント」に登録しておく

GA4 の **管理 → イベント** で、`contact_submit` を **キーイベント**（旧・コンバージョン）に
指定しておくと、レポートの主役として扱われます。イベントは一度発生しないと一覧に出てこないので、
公開後に自分で1回フォームを送ってから設定してください。

---

## 5. 自分のアクセスを除外する

自分で見た分が混ざると、数が少ないうちは特に読みにくくなります。

GA4 の **管理 → データストリーム → タグ設定を行う → 内部トラフィックの定義** で、
自宅や事務所のIPアドレスを登録し、**データフィルタ**を「有効」にしてください。

## プライバシーまわり

`/privacy/` に、取得している情報と外部への送信先をまとめてあります。
GA4 の設定は次のようにしてあり、プライバシーポリシーの記載と一致しています。

```js
gtag('config', gaId, {
  allow_google_signals: false,            // 広告向けのシグナルを送らない
  allow_ad_personalization_signals: false, // 広告のパーソナライズに使わせない
  anonymize_ip: true,
});
```

**EU圏からの閲覧が増える見込みがある場合は、同意バナーが別途必要になります。**
いまは入れていません。必要になったら言ってください。

## 実装がどこにあるか

| 何 | どこ |
|---|---|
| タグの読み込み | `src/layouts/Base.astro`（head、`gaId` があるときだけ出す） |
| イベント送信の共通処理 | `src/layouts/Base.astro` の `track()` と `window.ozTrack` |
| リンククリックの拾い方 | `src/layouts/Base.astro`（`document` の**捕捉側**で拾う） |
| フォーム送信の結果 | `src/pages/contact.astro` |

> リンクの計測を**捕捉側**（`capture: true`）で登録しているのには理由があります。
> 見出しの句点のリンクと隠しコマンドの面は、途中で `stopPropagation()` しているため、
> 通常の（バブリング側の）リスナーでは届きません。ここを変えると `line_click` が漏れます。
